# 世界书协作工作台（0.3.0）

面向 SillyTavern 1.19.0 的浏览器扩展。模型在正常聊天中使用工具，搜索、读取、修改或新建选定世界书里的条目。支持「先确认，再应用」和「模型直接修改」。

## 安装

在酒馆扩展管理器中使用以下仓库地址安装：

```text
https://github.com/cjhkcjgk3-sys/sillytavern-worldbook-workbench
```

也可以将整个仓库文件夹放进 SillyTavern 的 `public/scripts/extensions/third-party/`，确保文件夹根目录包含 `manifest.json`。重启或刷新酒馆，打开扩展设置中的「世界书协作工作台」。

这是一个原型。无需 Tavern Helper。需要 SillyTavern 1.19.0 和能正常使用工具调用的模型接口。

## 使用

1. 在酒馆的聊天补全设置中启用「工具调用 / Function Calling」，连接支持工具调用的模型。
2. 打开聊天输入框左下角的三横线，选择「世界书协作工作台」。启用聊天工具并选择**一本现有世界书**。新配置默认「直接修改，可撤销」，已保存的修改方式继续生效。
3. 在聊天中说：“搜索世界书中的王城条目，把位置从北方改为南方。”模型需要使用搜索、读取、提交工具。
4. 确认模式下，展开「待确认修改」查看修改前后，点击「确认并应用」；直接模式下会立即写入。
5. 在「修改记录与撤销」中查看记录和撤销。模型也可以新建条目：请它提供标题、关键词和正文。

扩展选择的世界书只决定模型工具操作哪一本。要让酒馆在日常聊天中根据世界书规则自动注入正文，仍需在酒馆原有世界书设置里绑定或启用该书，并设置条目关键词、激活方式等。新建条目采用酒馆默认条目配置和模型提供的关键词。

## 两楼世界书工作模式

在已保存的单人聊天中，从三横线菜单打开工作台，勾选「当前聊天使用世界书工作模式」，选好世界书。可以再从「编辑目标」点选一条，例如选中「设定」后直接说「精炼一下这条」。目标和开关保存在当前聊天里，换书后清除当前聊天的条目选择。

一次任务保存一条用户指令和一条最终回复。搜索、读取和提交结果在工作台的「最近一次世界书任务」里查看，修改、审批和撤销仍有各自记录。选中条目时，插件先读取该条目并把正文和版本信息随第一条模型请求发送，工具只允许处理这一条。选「由模型搜索条目」可以恢复整本书的工具范围。工具轮次沿用酒馆的函数调用上限。

此模式使用当前 OpenAI 或自定义聊天补全连接，需要启用函数调用。它向模型提供本条文字指令、已选条目和本次任务的工具结果，响应完成后统一显示。保留传统工具聊天方式，其他模型连接及普通角色聊天仍可通过关闭本模式继续使用。

## 边界与数据

- 原型依赖酒馆的**原生工具调用**，不提供文本指令解析后备方案；不支持工具调用的模型/接口不能使用聊天操作。
- 工具只开放搜索、读取、修改正文和新建条目；已有条目的标题、关键词和其他配置保持不变。没有批量删除功能。
- 新提案在生成时记录条目快照；应用或撤销时，如果该条目已变化会停止操作。跨浏览器或外部程序的极短时并发修改没有原子锁，建议不要同时在其他页面编辑同一本书。
- 提案与修改记录保存在**当前浏览器的 localStorage**，清理浏览器数据、更换浏览器或设备后不可用。写入前如果记录无法保存，操作会停止。建议另行导出世界书备份。
- 工具返回的条目内容和模型任务会发送给当前连接的模型服务；插件不单独读取模型密钥。
- 切换世界书后，只显示和操作当前选择的书对应的待确认项及记录。
- 功能依赖 1.19.0 的宿主上下文和世界书条目创建模块；升级酒馆后需要重新验证。

## 验证状态

0.3.0 在官方 SillyTavern 1.19.0、Chromium 和 OpenAI 兼容接口模拟服务上验证了聊天菜单入口、同名条目点选、拒绝修改非选中条目、直接写入、撤销和换书后清除目标。重开聊天后，修改和撤销合计仍只新增两条消息。用 320 和 390 像素宽的桌面触屏模拟检查了入口。真实模型服务、SillyDroid 设备及第三方总结插件仍需核验。

开发检查：在此文件夹运行 `npm test`（Node.js 18+）。
